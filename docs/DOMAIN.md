# DOMAIN.md — กติกาธุรกิจของร้าน (Lotus Desk)

> ไฟล์นี้ตอบคำถามจาก `docs/PLAN.md` หัวข้อ 8 — AI ต้องอ่านไฟล์นี้ก่อนเริ่ม M4 เป็นต้นไป
> อัปเดตล่าสุด: 2026-08-20

**สถานะ:** ตอบแล้ว 17/18 ข้อ — เหลือข้อ 9 (ตารางค่ามือจริง) ที่ต้องรอไฟล์จากเจ้าของร้าน
**ห้ามเริ่ม T6.2 (commission engine)** จนกว่าจะได้ตารางค่ามือจริงและสลิปย้อนหลัง 1 เดือนมาเป็น test fixture — ข้ออื่นตอบครบพอที่จะเริ่ม M4–M5 ได้แล้ว

## คิวและการจ่ายงาน

1. **คิวหมุนเรียงตามอะไร?**
   → เรียงตาม **เวลามาถึง** (มาก่อนได้คิวก่อน) — ไม่ใช้ชั่วโมงสะสม

2. **พนักงานที่ถูก "ลูกค้าขอ" เสียตำแหน่งคิวหมุนหรือไม่?**
   → **เสียตำแหน่ง** — นับเป็นงานปกติ ไม่ได้คิวพิเศษเพิ่ม

3. **งานที่ลูกค้ายกเลิกกะทันหัน พนักงานได้กลับต้นคิวหรือท้ายคิว?**
   → **กลับต้นคิว** (ไม่ใช่ความผิดพนักงาน)

4. **รับจองล่วงหน้าได้กี่วัน? ยกเลิกฟรีได้ถึงกี่ชั่วโมงก่อนนัด?**
   → รับจองล่วงหน้า **7 วัน** / ยกเลิกฟรีได้ถึง **2 ชั่วโมงก่อนนัด**

## คอร์ส

5. **คอร์สหมดอายุแล้วยังใช้ได้ไหม?**
   → **ใช้ได้ แต่ต้องผู้จัดการอนุมัติ** ทุกครั้ง (ไม่ใช้ได้อัตโนมัติ)

6. **โอนคอร์สให้คนอื่นได้ไหม? โอนได้บางส่วนหรือทั้งคอร์ส?**
   → **โอนได้ทั้งคอร์สเท่านั้น** — ห้ามโอนบางส่วน/แบ่งจำนวนครั้ง

7. **คืนเงินคอร์สที่ใช้ไปบางส่วนคิดอย่างไร?**
   → **หักตามราคาเต็มของครั้งที่ใช้ไปแล้ว** (ไม่ใช่หักตามสัดส่วน) — ร้านไม่เสียเปรียบ

8. **แช่แข็งคอร์สได้กี่วันต่อปี ต้องใครอนุมัติ?**
   → **30 วัน/ปี** ต้อง **ผู้จัดการ** อนุมัติ

## ค่ามือ

9. **โครงสร้างค่ามือปัจจุบันคืออะไร?**
   → รูปแบบหลัก: **เหมาต่อชั่วโมง** + **แยกเรตตามระดับพนักงาน** (Junior/Senior/Master คนละเรต)
   → **ยังไม่มีตารางตัวเลขจริง** — ⚠️ **ต้องขอจากเจ้าของร้านก่อนเริ่ม T6.2**:
     - [ ] ตารางค่ามือจริง ทุกบริการ × ทุกระดับพนักงาน × คิวหมุน/ลูกค้าขอ
     - [ ] สลิปค่ามือย้อนหลัง 1 เดือน (ใช้เทียบผลคำนวณให้ตรงทุกบาทตาม docs/PLAN.md §9)

10. **ตัดคอร์สคิดค่ามือจากอะไร?**
    → **เรตคงที่ที่ตั้งไว้ตายตัว** (ไม่ผูกกับมูลค่าหน้าบัตรหรือราคาขายจริง) — ต้องมีตารางเรตคงที่แยกต่างหากในข้อ 9

11. **ขายคอร์สได้คอมมิชชั่นเท่าไร ใครได้?**
    → **ไม่มีคอมมิชชั่นขายคอร์ส** — ระบบไม่ต้องคำนวณคอมมิชชั่นการขายคอร์สแยก

12. **ทิปเข้าใครทั้งหมด หรือหักเข้าร้านบางส่วน?**
    → เข้า **กองกลางพนักงานทุกคน** (ไม่ใช่ผู้ให้บริการคนเดียว, ไม่หักเข้าร้าน) — ต้องมีกติกาแบ่งกองกลาง (ดูข้อ T6.3 ในแผน ต้องถามเพิ่มว่าแบ่งตามเกณฑ์ใด เช่น เท่ากันทุกคน หรือตามชั่วโมงทำงาน)

13. **มีค่าปรับสาย/ขาดงานไหม หักอย่างไร?**
    → **ไม่มีค่าปรับ** — ใช้ระบบตักเตือนแทน (T6.1 ยังต้องคำนวณสาย/ขาด/OT เพื่อรายงาน แต่ไม่หักเงิน)

## ส่วนลดและการอนุมัติ

14. **แคชเชียร์ให้ส่วนลดเองได้กี่ % เกินนั้นใครอนุมัติ?**
    → **แคชเชียร์ให้ส่วนลดเองไม่ได้เลย** — ทุกส่วนลดต้องผ่านผู้จัดการอนุมัติ (PIN ผู้จัดการ)

15. **โปรโมชั่นซ้อนกันได้ไหม? ถ้าได้ ลำดับการคำนวณเป็นอย่างไร?**
    → **ซ้อนไม่ได้เลย** — ใช้ได้โปรโมชั่นเดียวต่อบิล ระบบเลือกโปรที่ลดมากที่สุดให้อัตโนมัติ
    → **ผลต่อ T5.3:** ปิดการใช้ `stackable=true` ทั้งระบบ (หรือไม่ต้องมีฟิลด์นี้เลย) เก็บแค่ `priority` เพื่อเทียบส่วนลดแล้วเลือกตัวที่ลดมากสุด

16. **ยกเลิกบิลหลังปิดรอบกะแล้ว ทำอย่างไร?**
    → **ต้องให้ผู้จัดการเปิดรอบกะใหม่ก่อน** ถึงจะยกเลิกบิลได้ (ตรงกับ T5.7 ที่ต้องบล็อกแก้บิลหลังปิดรอบ)

## ภาษีและบัญชี

17. **ร้านจด VAT ไหม? ต้องออกใบกำกับภาษีเต็มรูปหรือไม่?**
    → **ไม่จด VAT** — ยังไม่ต้องมีระบบภาษีมูลค่าเพิ่ม/ใบกำกับภาษีในเวอร์ชันนี้ (เผื่อช่องไว้ในอนาคตพอ ไม่ต้องสร้าง flow เต็มรูป)

18. **รับรู้รายได้จากคอร์สตอนขาย หรือตอนลูกค้าใช้บริการ?**
    → **ตอนลูกค้าใช้บริการ** (deferred revenue ตามหลักบัญชี) — ตรงกับ T7.2 ที่ต้องแยก "เงินเข้า vs รายได้รับรู้"

## จุดที่ต้องถามเจ้าของร้านเพิ่ม (พบระหว่างตอบคำถามหลัก)

- **ข้อ 12 (ทิปกองกลาง):** แบ่งกองกลางตามเกณฑ์อะไร — เท่ากันทุกคนที่เข้ากะ, ตามชั่วโมงทำงาน, หรือตามจำนวนใบงานที่ทำ? (มีผลต่อ T6.3 โดยตรง)
- **ข้อ 9/10:** เรตค่ามือ "คงที่" ต่างกันระหว่างคิวหมุนกับลูกค้าขอหรือไม่ (แผนเดิมถามไว้ว่าอาจต่างกัน)?

## เอกสารประกอบที่ต้องขอจากเจ้าของร้าน (ยังไม่ได้รับ)

- [ ] สลิปค่ามือย้อนหลัง 1 เดือน (ใช้เป็น test fixture เทียบผลคำนวณให้ตรงทุกบาท) — **บล็อกการเริ่ม T6.2**
