# Design System — "Gold & Sage"

## 1. ทิศทาง

โจทย์จริงของหน้าจอนี้คือ **พนักงานต้อนรับที่ต้องจัดคิวให้ถูกภายใน 10 วินาที ขณะที่ลูกค้ายืนรออยู่ตรงหน้า** ไม่ใช่หน้าเว็บขายของสปา ความสวยจึงต้องมาจากความสงบ ความคมของข้อมูล และการอ่านสถานะได้ในพริบตา — ไม่ใช่ภาพดอกไม้กับตัวอักษร serif

**เลือกอย่างจงใจ (ADR-057):** พื้นครีมอุ่น + ตัวอักษรน้ำตาลเข้ม + **ทอง/บรอนซ์** เป็นสีหลัก + **เขียวใบไม้** เป็นสีรอง — ปรับให้เข้ากับโลโก้ Sabaizy (มือถือดอกลีลาวดี สีทอง + ใบไม้เขียว บนพื้นครีม) เดิมเป็นปิโตรเลียมทีล (ADR-047) ตัวแปร CSS ยังใช้ชื่อ `--celadon*`/`--brass*` เดิมทั้งหมด (แค่เปลี่ยนค่า hex) ไม่ต้องแก้โค้ดที่อ้างอิงตัวแปร
**หลีกเลี่ยงอย่างจงใจ:** โทนสว่างจ้าหรือสีที่ contrast ไม่พอ — แม้เปลี่ยนไปทางครีม/ทองแล้ว ยังต้องอ่านสถานะได้ในพริบตาและผ่าน AA 4.5:1 เหมือนเดิม ไม่ลดทอนความคมของข้อมูลเพื่อความสวยงามอย่างเดียว

**Signature element:** *Lane Board* — กระดานคิวแนวนอน 1 แถว = 1 พนักงาน มี "รางคิวหมุน" อยู่ริมซ้ายและเส้นเวลาปัจจุบันสีทองเหลืองพาดทั้งจอ นี่คือหน้าจอที่ทั้งระบบถูกจดจำ ให้ลงแรงกับมันมากที่สุดและให้ที่เหลือเงียบ

## 3. สีสถานะ (ใช้ร่วมกันทั้งระบบ ห้ามคิดใหม่รายหน้า)

| สถานะ | สี | การใช้บน Lane Board |
|---|---|---|
| จองไว้ `booked` | indigo | พื้น tint + เส้นขอบประ |
| ยืนยันแล้ว `confirmed` | indigo | พื้น tint + spine ทึบ 3px |
| เช็คอินแล้ว `checked_in` | brass | พื้น tint + spine ทึบ |
| กำลังบริการ `in_service` | celadon | พื้นทึบ (ใช้ `--celadon-solid` ไม่ใช่ `--celadon`) ตัวอักษรขาว + ชีพจรจางที่ spine |
| เสร็จแล้ว `completed` | ink-faint | พื้น sunk ตัวอักษรจาง |
| ไม่มา `no_show` | rose | พื้น tint + เส้นทแยงจาง |
| ยกเลิก `cancelled` | — | ไม่แสดงบนกระดาน (ดูได้ในประวัติ) |

## 4. Typography

โหลดจาก Google Fonts เฉพาะน้ำหนักที่ใช้จริง (subset `thai,latin`)

| บทบาท | ฟอนต์ | การใช้ |
|---|---|---|
| Display | **Anuphan** 600 | ชื่อหน้า, ตัวเลข KPI, หัวการ์ด — ใช้อย่างจำกัด |
| Body / UI | **IBM Plex Sans Thai** 400/500/600 | ทุกอย่างที่เหลือ |
| Data | **IBM Plex Mono** 450 `tabular-nums` | เงิน, เวลา, รหัส, คอลัมน์ตัวเลขในตาราง |

```
display-lg  28/1.20  Anuphan 600   -0.01em   ← ชื่อหน้า
kpi         34/1.10  Anuphan 600   tnum      ← ตัวเลขบนแดชบอร์ด
h2          17/1.40  Anuphan 600
body        14/1.55  Plex Sans Thai 400
body-strong 14/1.55  Plex Sans Thai 600
label       12.5/1.35 Plex Sans Thai 500  --ink-muted
data        13/1.40  Plex Mono 450 tnum
```

**กฎเหล็ก:** ตัวเลขเงินและเวลา **ต้อง** เป็น `font-variant-numeric: tabular-nums` เสมอ ไม่งั้นคอลัมน์ในตารางจะเต้นและอ่านผิด

## 5. Layout & density

- Sidebar 240px (ยุบเหลือ 64px ได้) + Topbar 56px มีตัวเลือกสาขาและช่องค้นหาสากล (`Cmd/Ctrl+K`)
- Content max-width 1440px ยกเว้น Lane Board ที่กินเต็มจอ
- ตาราง: แถวสูง 40px โหมดปกติ / 32px โหมดแน่น (จำค่าไว้ต่อผู้ใช้)
- Spacing scale: 4 · 8 · 12 · 16 · 24 · 32 · 48
- **ห้ามใช้ modal ซ้อน modal** — ฟอร์มยาวให้ใช้ Sheet เลื่อนจากขวา
- เงา: ใช้เส้นขอบ 1px เป็นหลัก ใช้เงาเฉพาะ popover / dropdown / dialog

## 6. Motion

`--ease: cubic-bezier(.2,.8,.2,1)` ระยะ 120–180ms เท่านั้น

ใช้แค่ 4 ที่: บล็อกนัดตอนลาก, Sheet เลื่อนเข้า, Toast, และชีพจรจางบน spine ของงานที่กำลังบริการ
เคารพ `prefers-reduced-motion` ปิดทั้งหมด

## 7. คุณภาพขั้นต่ำ (ตรวจทุก PR ที่แตะ UI)

- โฟกัสคีย์บอร์ดมองเห็นชัด (`outline: 2px solid var(--celadon); outline-offset: 2px`)
- คอนทราสต์ผ่าน WCAG AA (ตัวอักษรปกติ ≥ 4.5:1)
- ทุกหน้าจอทำงานได้เต็มรูปแบบด้วยคีย์บอร์ดล้วน — พนักงานต้อนรับพิมพ์เร็วกว่าจิ้มเมาส์
- ทุกตารางมี empty state ที่บอกว่า "ทำอะไรต่อ" ไม่ใช่แค่ "ไม่พบข้อมูล"
- ข้อความ error บอกสาเหตุ + วิธีแก้ ห้ามขึ้นแค่ "เกิดข้อผิดพลาด"
- ปุ่มที่ทำให้ข้อมูลหาย/เงินเปลี่ยน ต้องใช้สี `--rose` และมีขั้นยืนยัน

## 8. การเขียนข้อความ (Copy)

- ใช้คำที่พนักงานพูดจริง: "ตัดคอร์ส" ไม่ใช่ "หักยอด package balance", "คิวหมุน" ไม่ใช่ "rotation assignment"
- ปุ่มบอกสิ่งที่จะเกิดขึ้น: "บันทึกการจอง" ไม่ใช่ "ตกลง"
- ชื่อ action ต้องเหมือนกันตลอดเส้นทาง: ปุ่ม "ปิดบิล" → toast "ปิดบิลแล้ว"
- ตัวเลขเงินแสดง `฿1,250` (ไม่มีทศนิยมถ้าลงตัว) เวลาแบบ 24 ชม. `14:30`

## 9. Mobile & Tablet UX (ADR-051, M10)

โจทย์: ผู้ใช้จอแคบคือพนักงานต้อนรับ/ผู้จัดการถือแท็บเล็ตเดินในร้าน หรือเจ้าของร้านเช็คยอดผ่านมือถือ — pattern
เดิมทั้งหมด (sidebar ถาวร, ตารางกว้าง, Sheet ขวากว้างคงที่, Lane Board grid เวลา×คน) คิดมาเพื่อจอ ≥ 1024px
เท่านั้น หัวข้อนี้เพิ่ม pattern สำหรับจอแคบ **โดยไม่แทนที่ของเดิมบนจอกว้าง**

### 9.1 Breakpoints

ใช้ค่า default ของ Tailwind v4 (ไม่ override `screens` ใน `packages/ui/src/tailwind-theme.css`)

| โหมด | ช่วงจอ | Navigation |
|---|---|---|
| **Mobile** | < 768px (`< md`) | Bottom tab bar |
| **Tablet** | 768–1023px (`md`–`<lg`) | Sidebar ย่อ 72px ไอคอนล้วน (ADR-047) เป็นค่าเริ่มต้น |
| **Desktop** | ≥ 1024px (`lg`+) | Sidebar เต็ม 240px ตาม §5 เดิม |

### 9.2 Bottom tab bar (Mobile)

แทนที่ hamburger + drawer เดิมของ `AppShell` เมื่อจอ `< md`: แสดง **4 เมนูหลัก + "เพิ่มเติม"** เสมอ
(กระดานคิว, บิล/แคชเชียร์, สมาชิก, แดชบอร์ด — เลือกจาก 6 เมนู Basic Package ตาม ADR-050) ปุ่มที่ 5 เปิด
sheet เลื่อนจากล่างแสดงเมนูที่เหลือตามสิทธิ์ผู้ใช้ (รายการเดียวกับที่ `nav-items.tsx` filter อยู่แล้ว)
สูง 56px + `env(safe-area-inset-bottom)`, ไอคอน active ใช้ `--celadon` / ไม่ active ใช้ `--ink-muted`,
พื้นที่กดต่อปุ่ม ≥ 44×44px

### 9.3 Component pattern ใหม่ (`packages/ui`)

- **`ResponsiveList`** — แทน `Table` บนจอ `< md`: component เดียวกันตัดสินใจ layout เองตาม breakpoint
  (ไม่แยกหน้าคู่ขนาน) รับ `columns` เดิม + `mobileCard: (row) => ReactNode` ต่อหน้า ทั้งการ์ดเป็น tap target
  เดียวเปิด Sheet/รายละเอียดเดิม ตัวเลขยังคง `tabular-nums` เสมอ
- **`Sheet`** เพิ่มโหมด full-screen bottom sheet บนจอ `< md`: เลื่อนจากล่าง, สูงเต็มจอลบ safe-area, มีแถบจับ
  บนสุดปัดลงเพื่อปิด, ปุ่ม "บันทึก" ตรึงล่างสุดเสมอ — ยังคงกติกา "ห้าม modal ซ้อน modal" จาก §5 เดิม
- **FAB** — เฉพาะหน้าที่มี action หลักเดียวชัดเจน (สมาชิก, พนักงาน, บริการ, ห้อง/เตียง, คอร์ส/แพ็กเกจ)
  มุมขวาล่างเหนือ bottom tab bar 16px สี `--celadon-solid` แทนปุ่ม "+" บนสุดเดิมเฉพาะบนจอ mobile

### 9.4 รายหน้าที่ต่างจาก pattern ทั่วไป

| หน้า | Mobile pattern |
|---|---|
| **กระดานคิว (Lane Board)** ★ | มุมมอง "รายคน" แนวตั้ง: เลือกพนักงานจาก chip เลื่อนแนวนอนบนสุด → timeline agenda แนวตั้งของคนนั้น รางคิวหมุนเป็นแถบเลื่อนแนวนอนใต้ chip **ไม่ทำ drag-and-drop บนมือถือ** ใช้ sheet "ย้ายเวลา/ย้ายคน" แทน |
| **ตารางกะ** | เลือกพนักงาน 1 คนจาก dropdown → การ์ดกะรายวันแนวตั้ง 7 วัน แทนตาราง 2 มิติ แก้กะผ่าน Sheet |
| **บิล/แคชเชียร์** ★ | Wizard 3 ขั้นแนวตั้ง (เลือกรายการ → ชำระเงิน → ยืนยัน/ใบเสร็จ) ปุ่มถัดไป/ย้อนกลับตรึงล่าง แถบความคืบหน้าบนสุด |
| **โปรโมชั่น+ทดลองคำนวณ** | คอลัมน์เดียว: ตะกร้าจำลองพับ/ขยายได้ ผลลัพธ์อยู่ล่างสุดเสมอ |
| **รายงาน** | ตัวกรองพับเป็น Sheet, กราฟคอลัมน์เดียวเลื่อนแนวตั้ง, ตารางดิบใช้ `ResponsiveList` |
| ที่เหลือ (พนักงาน/ห้อง/บริการ/สมาชิก/คอร์ส/ค่ามือ/ลงเวลา) | `ResponsiveList` + FAB + full-screen Sheet ตามมาตรฐาน §9.3 ไม่มีข้อยกเว้น |

★ = งานเสี่ยงสูง ตรวจโค้ดเองก่อน merge (เกณฑ์เดียวกับ ★ ใน PLAN.md)
